# AI augmentation workers

Both workers consume CG images generated by `synthetic_core/cg_exporter`, upload
the RGB image and mask through the ComfyUI HTTP API, submit the checked-in API
workflow, and download the selected final image through `/view`. The worker and
ComfyUI therefore do not need a shared filesystem.

## Runtime contract

Configuration precedence is CLI option, then environment variable, then the
repository default. `OUTPUT_ROOT` defaults to `<repo>/outputs`, and `BATCH_ID`
defaults to `demo_001`.

`.env.example` is a shell environment template; the Python workers do not add
a dotenv dependency. To use a copied file, export it from the repository root:

```bash
cp .env.example .env
set -a
. ./.env
set +a
```

Endpoint resolution:

- Flux: `--comfy-url`, `FLUX_COMFYUI_URL`, `COMFYUI_URL`, then `http://127.0.0.1:8188`.
- Qwen: `--comfy-url`, `QWEN_COMFYUI_URL`, `COMFYUI_URL`, then `http://127.0.0.1:8188`.

The existing `configs/worker.json` files are reference metadata for workflow
node mappings; the current Python entrypoints do not load them. Runtime values
come from the CLI and environment contract above.

A single shared ComfyUI instance is the default. Set the route-specific
variables when using separate instances. GPU visibility is intentionally not
set in repository code; for example, a deployment may run
`CUDA_VISIBLE_DEVICES=0 workers/flux2_worker/launch_comfyui.sh`.

Outputs use this layout:

```text
<OUTPUT_ROOT>/<batch_id>/
  cg/sample_000001/{image.png,image_mask.png,metadata.json}
  ai_augmented/flux2/sample_000001/image.png
  ai_augmented/qwen/sample_000001/image.png
  auxiliary/{flux2,qwen}/...
  batch_manifest.json
```

Artifact paths stored in `batch_manifest.json` are relative to the batch root.
Existing CG artifacts are reused unless `--overwrite` is supplied, so both
augmentation routes can operate on the same batch.

## ComfyUI requirements

The workflow JSON files are the source of truth. This repository does not ship
or download model weights.

Flux workflow model filenames:

- `flux2_dev_fp8mixed.safetensors`
- `mistral_3_small_flux2_bf16.safetensors`
- `full_encoder_small_decoder.safetensors`

The default workflow has `Enable 8 steps lora = false`, so
`Flux_2-Turbo-LoRA_comfyui.safetensors` is optional. It is required only when
the Turbo switch is enabled. Flux preflight follows the selected lazy switch
branch when classifying model files as required or optional.

`ComfySwitchNode` is a ComfyUI core node, not a third-party custom node. The
installed ComfyUI version must be recent enough to provide it; node-class
preflight still fails when `ComfySwitchNode` is unavailable.

Qwen workflow model filenames:

- `qwen_image_fp8_e4m3fn.safetensors`
- `qwen_2.5_vl_7b_fp8_scaled.safetensors`
- `qwen_image_vae.safetensors`
- `Qwen-Image-InstantX-ControlNet-Inpainting.safetensors`

Qwen additionally requires the non-core class types
`ControlNetInpaintingAliMamaApply` and `ResizeImageMaskNode`.

The exported workflows do not identify the package repositories that provide
those class types, so this project deliberately does not guess package names.
Use ComfyUI's missing-node tooling for the target installation. At startup the
worker queries `/object_info` and reports missing class types or referenced
model filenames before submitting a job.

## Commands

Dashboard (localhost only by default):

```bash
workers/flux2_worker/launch_worker.sh
workers/qwen_inpainting_worker/launch_worker.sh
```

CLI examples:

```bash
python3 workers/flux2_worker/massive_production.py \
  --n 10 --batch-id batch_001 --output-root ./outputs

python3 workers/qwen_inpainting_worker/massive_production.py \
  --n 10 --batch-id batch_001 --output-root ./outputs
```

For ComfyUI, set `COMFYUI_ROOT`; choose the deployment GPU outside the scripts:

```bash
COMFYUI_ROOT=/opt/ComfyUI CUDA_VISIBLE_DEVICES=0 \
  workers/flux2_worker/launch_comfyui.sh
```
